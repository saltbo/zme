# API inventory and breaking change: 2026-08-04

The prior unversioned API mixed provider names and action verbs into routes. Repository inventory covered every `server/http` registration and every `src/lib/api` caller. This release removes those shapes rather than maintaining a second semantic model.

| Previous shape | Current resource shape |
| --- | --- |
| provider media search/trending/popular/discover/genres routes | `/media`, `/media-trends`, `/popular-media`, `/media-recommendations`, `/media-genres` |
| `/books/search`, `/books/discover` | `/books`, `/book-recommendations` |
| `/music/search`, `/music/discover`, `/music/details` | `/music`, `/music-recommendations`, `/music/{mediaKey}` |
| indexer search action | `/release-candidates` for the human UI; persistent Agent workflow uses `/release-search-jobs` and results |
| connector sync/continue actions | persistent `/connector-sync-jobs` resources and `PUT /connector-login-attempts/{id}/response` challenge responses |
| component health actions | latest-state `/media-sources/{id}/health`, `/indexers/{id}/health`, `/downloaders/{id}/health` resources |
| per-track download action | `/music-download-tasks`; signed content is `/music/tracks/{id}/content` |

The complete HTTP contract is published at `/api/openapi.json`. It includes media lookup, persistent release-search jobs/results, credential-free download-destination discovery, download tasks, and every browser-session operation registered below `/api`, including accurate query/body schemas, path types, SSE, audio, redirect, and conditional-request semantics. Browser-session configuration and credential surfaces use only the `oidcSession` security scheme and are not Agent-requestable capabilities. Contract tests compare the production Hono route table to the document and audit request/response media types, parameters, operation IDs, and DPoP scopes. CI also compares the generated semantic signature to the reviewed release baseline.

The SPA and Realmroot Agent share the same current API contract; calls do not carry a protocol-version or entity-tag precondition header. Create operations in the Resource API require an idempotency key. Collections are page-bounded. Every JSON error is normalized to `application/problem+json`.

Release-search jobs are resumable on reads after an interrupted Worker request; concurrent recovery writes are idempotent and cannot downgrade a completed job. Download tasks separate downstream acceptance (`submitted`) from progress (`running`) and terminal states (`completed`, `failed`, or `canceled`). Agent destination discovery includes only adapters with exact per-task status lookup. Task reads synchronize downstream byte counts, rates, status, and result metadata with monotonic conditional writes, so a late active snapshot cannot overwrite a terminal state. A stale `submitting` task is failed safely instead of being resubmitted and risking a duplicate downstream mutation.
